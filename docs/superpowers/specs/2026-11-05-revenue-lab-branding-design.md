# 수익실험실 브랜드 전환 설계

## 목표

사이트의 브랜드성 `0 → 1` 표기를 검색 의도가 명확한 `수익실험실`로 통일한다. 기존 `/lab/` 주소와 링크 자산은 보존한다.

## 공개 표면

페이지 제목·콘텐츠·메타데이터의 브랜드는 `수익실험실`로 변경한다. 전역 메뉴는 후속 사용자 결정에 따라 영어 라벨 `Revenue Lab`을 사용한다.

- Jekyll 전역 메뉴: `Revenue Lab`
- React Community 전역 메뉴: `Revenue Lab`
- 홈페이지 front matter 제목과 H1
- `/lab/` 페이지 제목, H1, 설명
- About 페이지의 브랜드 소개 문구
- 브라우저 `<title>`
- Open Graph 및 Twitter Card 제목·설명·이미지
- 정적 사이트 검증기의 route 제목 계약

과거 글에서 창업·제품 개발 또는 기술 동작을 설명하는 일반 표현 `0→1`은 브랜드가 아니므로 변경하지 않는다. Kubernetes replica 전환과 같은 기술 표현도 유지한다. 과거 설계 문서는 당시 계약 기록이므로 소급 수정하지 않는다.

## URL과 SEO

- canonical URL `/lab/`를 유지한다.
- 새 slug나 redirect를 만들지 않는다.
- 홈페이지와 `/lab/`의 title, description, H1에 `수익실험실`을 직접 포함한다.
- 페이지 설명은 과장된 수익 주장을 피하고 실제 범위인 수익모델 실험·검증·기록을 설명한다.
- OG/Twitter 메타데이터는 공통 layout이 페이지 front matter를 사용하므로 해당 front matter와 대표 이미지를 단일 진실 공급원으로 유지한다.

## 배너

누락된 기존 `/images/2026-02-24-Zero-To-One-Dashboard/cover.jpg` 참조를 제거하고 새 로컬 1600×900 PNG 배너를 사용한다.

- 제목: `수익실험실`
- 보조 문구: `코드와 자동화로 수익모델을 검증합니다`
- 시각 방향: 기존 페이지와 맞는 짙은 남색 배경, 노란 포인트, 실험·측정·반복을 나타내는 추상 그래픽
- 한글 글리프가 이미지에 정확히 렌더링되는 로컬 폰트를 사용한다.
- 홈페이지와 `/lab/`가 같은 대표 이미지를 사용해 브랜드 공유 카드를 일관되게 만든다.
- 이미지에 외부 리소스나 추적 요소를 포함하지 않는다.

## 테스트와 검증

1. 브랜드 계약 테스트를 먼저 실패시킨다.
2. Jekyll/React 공개 표면에서 브랜드성 `0 → 1`이 남지 않았는지 검사한다.
3. 일반 기술·과거 글의 의미 있는 `0→1` 표현은 검사 대상에서 제외한다.
4. React 헤더 테스트, 타입 검사, 린트, 빌드를 실행한다.
5. 정적 사이트 verifier의 홈페이지와 `/lab/` 제목 기대값을 변경하고 verifier 자체 테스트를 실행한다.
6. Docker `site` target으로 최종 artifact를 생성해 title, canonical, OG/Twitter, 배너 파일 존재와 참조를 검증한다.
7. 로컬 HTTP·dev·CDP 서버는 실행하지 않는다.

## 전달 범위

검증된 feature branch를 한 번 push한다. PR 생성, master merge, GitHub Pages 배포는 수행하지 않는다.
