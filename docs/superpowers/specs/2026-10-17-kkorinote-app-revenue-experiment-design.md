# 꼬리노트 앱 출시 수익 실험 포스팅 설계

## 목적

트레이딩 이후의 다음 수익 실험을 추상적인 “후보 탐색”에서 실제 제품 개발로 전환한다. 첫 앱은 반려동물 건강·일상 기록 앱 **꼬리노트(KkoriNote)**이며, 준우가 1인 개발로 MVP를 만들고 무료 다운로드에서 광고와 인앱결제로 이어지는 수익 구조를 검증한다.

## 현재 사실과 공개 경계

- 꼬리노트는 현재 개발 중이다.
- Apple Developer 등록을 완료했다.
- App Store 심사 제출·승인·출시·다운로드·매출은 아직 완료 사실로 표현하지 않는다.
- Apple Developer 등록과 App Store 출시를 같은 상태로 취급하지 않는다.
- 수익 예상치는 가정이며 실제 수익으로 표시하지 않는다.
- 반려동물 건강 데이터를 진단·처방에 사용하지 않고 기록·알림 도구로 한정한다.

### 3. 수익실험실 갱신

`_pages/lab.md`에서 다음 수익모델 상태를 “연구 중”에서 “꼬리노트 개발 중”으로 구체화한다. 별도 앱 실험 섹션에 다음을 공개한다.

- 제품: 반려동물 건강·일상 기록
- 현재 단계: MVP 개발 중
- 완료: Apple Developer 등록
- 미완료: App Store 제출·승인·출시·매출 검증
- 수익 가설: 무료 다운로드, 비민감 화면의 제한적 광고, 광고 제거·다중 반려동물·가족 공유·리포트·백업 등의 인앱결제
- AI 원칙: 월간 기록 요약 같은 선택형 부가기능, 사용량 제한, 의료 판단 금지
- 검증 순서: 개발 → 내부 테스트 → 심사 제출 → 출시 → 유지율·광고·결제 전환 측정

상태 페이지의 최근 업데이트 날짜를 `2026-10-17`로 변경한다.

## 사실 검증과 출처

외부 사실은 다음 우선순위로 확인한다.

1. Apple App Review Guidelines: 디지털 기능 잠금 해제와 인앱결제, 광고·건강정보 관련 제한
2. Apple Developer 또는 App Store Connect 공식 문서: 등록과 출시 단계의 차이
3. Apple Small Business Program 공식 문서: 적용 조건과 수수료를 언급할 경우에만 인용
4. RevenueCat 2026 보고서: 카테고리별 결제 성과는 조사 범위·표본·지표를 보존하고 일반 시장 전체로 확대하지 않음
5. OpenAI 공식 가격표: AI 단위경제 예시를 넣을 경우 게시 시점 가격을 다시 확인하고 모델·토큰·환율 가정을 명시

사용자가 제공한 추천 목록과 비용 계산은 아이디어 선택 배경으로 활용하되, URL 추적 파라미터를 제거하고 원문을 직접 확인한 뒤 인용한다. 확인되지 않은 eCPM·환율·전환율은 사실이 아니라 시나리오 가정으로 표시한다.

## 수익모델 표현

추천 구조는 다음과 같다.

- 무료: 반려동물 1마리, 기본 기록·알림·타임라인
- 광고: 건강·투약·병원 기록 흐름을 방해하지 않는 비민감 화면에 제한
- 일회성 IAP: 광고 제거 또는 초기 Pro 기능 후보
- 구독 후보: 가족 공유, 클라우드 동기화·백업, 장기 리포트처럼 지속 비용이 있는 기능
- AI 크레딧 후보: 선택 기간 요약 등 서버 비용이 발생하는 기능에만 적용

정확한 가격은 아직 검증 전 가설로 남긴다. 광고와 구독을 동시에 과도하게 넣지 않고 MVP에서는 기록 습관과 재방문을 먼저 검증한다.

## 기존 콘텐츠와의 경계

- 기존 수익실험실의 트레이딩 종료 기록은 수정하지 않는다.
- 일반적인 AI 앱 수익성 분석 글이 아니라 꼬리노트라는 실제 첫 제품의 시작 기록으로 쓴다.
- 앱이 출시됐거나 수익을 냈다고 표현하지 않는다.
- 제품 개발 세부 PRD 전체를 포스트에 복사하지 않고 사용자 문제, 수익 가설, 검증 단계만 전달한다.

## 검증 기준

- 신규 포스트 front matter와 `## Sources` 계약 통과
- 외부 사실의 문장별 인용과 Sources 최초 등장 순서 `1..N`
- 배너 HTTP 성공, 1600×900, front matter와 첫 본문 이미지 일치
- 메인홈·수익실험실·포스트의 제품명과 상태 문구 일치
- `Apple Developer 등록 완료`와 `App Store 출시 전`이 동시에 명확히 표시됨
- `출시 완료`, `승인 완료`, `매출 발생` 같은 거짓 현재형 표현 없음
- Docker/Jekyll 통합 빌드와 artifact verifier 통과
- 생성된 포스트 route와 메인·수익실험실 HTML에서 상태 문구 직접 확인
- 검증 완료 후 Codex `humanize-korean`을 보수적으로 적용하고 사실·수치·인용·URL 보존 재검사

## 전달 범위

최종 구현은 별도 feature branch에 커밋하고 원격 branch까지 push한다. 사용자가 직접 PR을 만들 수 있도록 compare 링크를 제공한다. merge, `master` 직접 push, Pages 배포는 수행하지 않는다.
