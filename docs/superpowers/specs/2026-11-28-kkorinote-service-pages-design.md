# 꼬리노트 서비스 페이지 설계

## 목표

breadlab.ai GitHub Pages에 꼬리노트의 App Store 마케팅·개인정보처리방침·이용약관·지원 페이지를 게시한다. 앱에 하드코딩된 다음 HTTPS 경로가 확장자 없이 동작해야 한다.

- `https://breadlab.ai/kkorinote/`
- `https://breadlab.ai/kkorinote/privacy/`
- `https://breadlab.ai/kkorinote/terms/`
- `https://breadlab.ai/kkorinote/support/`

`app-ads.txt`는 변경하지 않는다.

- 개인정보 보호책임자: `김준우`

- 개인 이메일 `developer.joon@gmail.com`은 소스, 테스트 fixture, 생성 결과물에 게시하지 않는다.

## 구현 방식

꼬리노트 전용 Jekyll 레이아웃과 스타일시트를 추가하고, 네 페이지는 Markdown 컬렉션 문서로 작성한다.

- `_layouts/kkorinote.html`: 꼬리노트 전용 HTML 문서 셸
- `_includes/kkorinote-footer.html`: 네 페이지 공통 푸터
- `css/kkorinote.css`: 전용 반응형·다크 모드 스타일
- `_pages/kkorinote-index.md`: 소개
- `_pages/kkorinote-privacy.md`: 개인정보처리방침
- `_pages/kkorinote-terms.md`: 이용약관
- `_pages/kkorinote-support.md`: 지원

각 문서는 trailing slash permalink를 사용해 Jekyll이 해당 경로의 `index.html`을 생성하게 한다. 전용 레이아웃은 기존 사이트의 공용 레이아웃을 상속하지 않는다. 기존 공용 레이아웃에는 AdSense, Facebook, Giscus 및 선택적 Analytics 코드가 있기 때문이다.

## 페이지 구조

### 소개

- 앱 이름 `꼬리노트`
- 한 줄 소개 `반려동물의 투약·증상·병원 기록을 한곳에.`
- 투약·접종 알림, 기록 타임라인, 병원용 PDF 리포트, iCloud 함께 돌보기
- 개인정보 원칙 문구
- 비활성 링크 대신 `곧 출시` 상태 표시
- 앱 아이콘과 스크린샷은 원본이 제공될 때 추가하며, 이번 범위에는 빈 자리나 임시 이미지를 두지 않는다.

### 개인정보처리방침

전달받아 기존 브랜치에 기록된 본문을 유지하되 다음을 반영한다.

- 잘못된 `/kkorinote/pricacy` 경로를 `/kkorinote/privacy/`로 수정
- 첫 문단의 운영자 표기를 확정값으로 교체
- 시행일을 실제 게시일로 교체
- 9항 이메일을 공개 문의 이메일로 교체
- 3항과 7항은 전달된 교체 본문을 유지

### 이용약관

- Apple 표준 EULA 적용과 공식 링크
- 모든 기능 무료, 설정·반려동물 목록 화면 광고 표시
- 광고 제거 비소모성 1회 구매, 구매 복원, Apple 환불 정책
- 의료 면책과 알림 한계
- 로컬·iCloud 저장 및 이용자 백업 책임
- 함께 돌보기 공유 범위와 권한 회수
- 약관 변경·시행일·지원 링크

### 지원

- 공개 문의 이메일과 영업일 2~3일 답변 안내
- 앱 버전, iOS 버전, 기기 모델, 증상을 문의 정보로 안내
- 반려동물 건강 기록 내용을 보내지 않도록 명시
- 알림, iCloud, 함께 돌보기, 구매 복원, 데이터 삭제·내보내기, 광고 개인정보 설정 FAQ

## 시각·접근성 방향

디자인 방향은 `따뜻하고 차분한 반려동물 건강 기록 문서`다.

- 본문 최대 폭 `720px`
- 모바일 좌우 여백 최소 `16px`
- 본문 기본 크기 `17px`, 최소 `16px` 이상
- 편안한 줄 높이와 명확한 제목 계층
- `prefers-color-scheme: dark` 기반 다크 모드
- 링크와 버튼의 `:focus-visible` 표시
- 긴 표는 페이지 전체가 아니라 표 래퍼 안에서만 가로 스크롤
- 긴 이메일과 URL은 안전하게 줄바꿈
- 마케팅 페이지는 간결한 히어로와 기능 목록을 사용하고, 법률 문서는 장식보다 가독성을 우선한다.

## 개인정보·보안 경계

- 광고, 분석, 사용자 추적 스크립트를 포함하지 않는다.
- 기존 공용 레이아웃의 외부 JavaScript를 상속하지 않는다.
- CSS와 HTML은 저장소의 로컬 정적 파일만 참조한다.
- 공개 이메일 외 개인 이메일이 저장소 변경분이나 생성 결과에 나타나면 검증 실패로 처리한다.
- 앱 건강 기록을 광고에 사용하지 않는다는 정책 문구를 유지한다.

## 검증 계약

테스트를 먼저 작성하고 실패를 확인한 뒤 구현한다.

1. 빌드 산출물에 네 개의 정확한 `index.html` 경로가 존재한다.
2. 각 페이지의 title, canonical URL, 핵심 문구가 페이지별로 일치한다.
3. 모든 페이지에 저작권과 개인정보처리방침·이용약관·지원 링크가 있다.
4. 생성된 네 HTML에 광고·분석·추적 스크립트가 없다.
5. 개인 이메일, 대괄호 자리표시자, `TODO`, `TBD`, 잘못된 `pricacy` 경로가 없다.
6. CSS에 최대 폭, 모바일 여백, 최소 글자 크기, 다크 모드 및 overflow 방지 규칙이 있다.
7. `app-ads.txt`는 기준 브랜치와 동일하다.
8. Jekyll 빌드, 꼬리노트 집중 검증, 기존 사이트 검증을 실행한다.
9. 사용자가 결과 화면이나 브라우저 검증을 요청하지 않았으므로 로컬 HTTP 서버는 시작하지 않는다. 모바일 가로 스크롤은 생성 DOM/CSS 계약으로 검증하고, 실제 iPhone Safari 수동 검증은 별도 상태로 보고한다.
