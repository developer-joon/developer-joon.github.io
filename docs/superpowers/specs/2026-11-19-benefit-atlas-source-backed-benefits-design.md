# Benefit Atlas 출처 기반 구체 혜택 조사 설계

## 결정과 목표

현재 2,000개 기업 원장과 950개 추가 조사 projection은 유지한다. 사용자가 실제로 볼 것은 회사 이름이나 분야 상태가 아니라 **출처에 명시된 개별 복지 항목**이다. 공개 승인 혜택이 0건인 동안 기업 정보만 나열하는 현재 기본 화면은 유용하지 않다. 사용자는 다음 공개 표현을 선택했다: 출처 기반 개별 혜택을 `조사 중`으로 별도 표시하고, 기본 목록에서 아직 이 항목이 없는 기업을 제외한다.

목표는 2,000개 대상에서 가능한 한 많은 기업의 **서로 다른** 혜택을 계속 조사하는 것이다. 첫 내부 검증 단위는 권리와 법인 연결을 확인할 수 있는 공식 기업 출처 시범군으로 제한하며, 조사 대상을 모두 마쳤다는 표현은 금지한다. 조사 진행과 원격 출고는 다른 단계다. 앞서 요청한 대로 전체 변경의 원격 브랜치 push는 마지막 한 번만 한다. PR·merge·배포는 별도 요청 없이는 하지 않는다.

## 데이터와 신뢰 경계

각 조사 항목은 회사의 제공 행동 하나, 회사의 정확한 법인 ID, 출처 URL, 한 가지 주 분야, 출처가 명시한 대상·조건·금액/기간/지역, 관찰 시각, 현재성, 법인 귀속·권리 상태를 가진다. 한 페이지의 여러 혜택을 별도 항목으로 분리하고, 같은 혜택의 여러 출처는 하나의 항목에 묶는다. 일반적인 법정 의무, 회사 문화·채용 홍보, 통계·검색 페이지, 관계사·그룹 전체의 정책을 선택 법인의 혜택으로 옮기지 않는다. 공개 출처의 본문 덤프나 분야 간 공통 인용을 혜택 문장으로 재사용하지 않는다.

원시 취득, 비공개 atomic research lead, 독립 근거·의미·권리 검토, 출처 기반 공개 `조사 중` 항목, 독립 승인된 `확인된 혜택`은 서로 다른 상태와 분모다. 기존 `verified_benefits` 및 승인 수는 변경하지 않는다. `조사 중`은 정식 승인 혜택 수나 조건 일치 추천 점수에 더하지 않는다. 근거 없거나 접근이 막힌 항목은 `조사 미완료`이며 복지가 없다는 뜻이 아니다. 과거 자료와 적용 대상 미상은 반드시 그 사실을 함께 노출한다.

공개 연구 항목에는 재사용 권리가 확인된 간결한 **자체 요약문**과 출처·적용 범위만 싣고 원문 인용은 기본적으로 싣지 않는다. 출처별 claim-specific 허용 근거가 없으면 인용문·원시 본문·비공개 법인 식별 자료는 공개 artifact와 Git에 넣지 않는다. snapshot/retention이 금지된 자료는 전체 본문을 비공개 작업 공간에도 보존하지 않고 허용된 URL·짧은 메타데이터·다이제스트만 유지한다. 검색 snippet은 발견 경로이지 출처 검증이 아니다.

## 공개 구조와 화면

기존 2,000개 기본 manifest와 승인 v2 projection을 **바이트 단위로 보존**하고, 별도의 버전·해시·기준 manifest SHA를 가진 연구 항목 sibling artifact를 생성한다. 생성기는 고정된 비공개 입력 목록, 독립 검토 결과, 권리 결정을 검증한 후에만 공개할 항목을 결정한다. 수동 JSON 조작이나 기존 검증/승인 ledger 덮어쓰기는 금지한다. 브라우저는 선언된 연구 artifact의 크기·해시·형식·회사 ID·출처 HTTPS를 검증하고, 불일치 시 연구 항목을 fail-closed로 표시하지 않는다.

목록 기본값은 **하나 이상의 공개 가능한 출처 기반 구체 항목이 있는 회사**만 보여준다. 사용자는 전체 조사 기업 2,000개를 명시적 필터로 볼 수 있지만, 이를 복지 제공 기업 수로 부르지 않는다. 상세는 분야별 atomic 항목 아래 `회사 출처에 기재 · 조사 중`, 원문에서 확인된 조건, `현재성 확인 필요` 등의 한계, 출처 링크와 확인 시각을 표시한다. 별도 `확인된 혜택` 섹션과 0건 수치는 그대로 유지한다. 승인 전 조사 항목은 맞춤 조건 적합 판정이나 공식 비교의 검증 수에 들어가지 않는다.

## 첫 시범군과 계속 조사

먼저 동결된 원장의 E1·유니셈·HMM·오성첨단소재와 기존 양성 조사 단서 중 권리 재확인이 가능한 후속 기업에서 출처를 다시 관찰하고 혜택을 분리한다. 모든 후보는 정확한 회사 ID와 출처 URL로 할당하고, 기업별 취득 파일·권리 판정·거절 사유·중복 키를 보존한다. 원본 2,000개 분모와 공개 승인 0건을 유지한 채 실제 출처 기반 표시 기업과 개별 항목의 수를 별도로 검산한다. 시범군의 검토/빌드가 통과해도 전체 조사 완료로 선언하지 않는다. 이후 고정된 25개 법인 배치를 중복 없이 순회하고, 조사 시도·출처 단서·현재성·정확 법인 귀속을 재검토한다.

## 실패 처리와 검증

- 출처 본문이 확보되지 않거나 짧은 문구가 실제 출처와 맞지 않으면 `research_only`로 남긴다. 출처 권리, 법인, 지역·직군, 현재성에 문제가 있으면 공개 항목에 올리지 않는다.
- 테스트는 한 페이지의 여러 혜택 분리, 같은 혜택의 중복 제거, 다른 법인·분야 전이 거부, 권리 없는 인용 금지, 기본 목록의 미조사 제외, 전체 목록의 비부재 표시, 승인 수 0 유지, 잘못된 descriptor fail-closed를 실제 산출물 기준으로 검증한다.
- Node/프런트엔드 전체 검사와 Docker 단일 정적 산출물 검증 후에만 원격 출고 여부를 결정한다. 서버 실행이나 추가 브라우저 라이브러리 다운로드는 하지 않는다. 이번 작업에서 현행 공개 사이트를 변경했다고 보고하려면 실제 원격 push/배포 및 라이브 읽기 검증이 있어야 한다.
