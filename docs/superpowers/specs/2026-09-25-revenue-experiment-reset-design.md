# 수익 실험 상태 현행화 설계

## 목적

사이트의 현재형 상태를 실제 운영 상태와 맞춘다. 코인 자동매매는 중단·보류됐고 기존 포지션은 정리됐다는 사실을 명확히 공개한다. 오래된 평가액을 현재 자산처럼 제시하지 않고, 현재는 다른 수익모델을 연구 중이라는 방향을 메인·수익실험실·관련 프로젝트 페이지에서 일관되게 보여준다.

## 확인된 사실

- 코인 자동매매는 중단·보류됐다.
- 기존 코인 포지션은 정리됐다.
- 현재 다른 수익모델을 연구 중이다.
- 최종 실현손익과 현재 투자 자산 총액은 제공되지 않았다.
- 수익실험실의 307만 원은 2026년 4월 당시 스냅샷이다.
- 2026년 5월 24일 트레이딩 글의 3,085,757원도 종료 시점 정산값이 아니라 당시 스냅샷이다.

## 편집 원칙

1. 제공되지 않은 최종 손익과 현재 자산 수치를 추정하지 않는다.
2. 과거 포스트의 당시 수치와 서술은 역사적 기록이므로 수정하지 않는다.
3. 현재 상태를 나타내는 페이지에서만 오래된 `LIVE`, `운영 중`, 진행 중 포지션 문구를 제거한다.
4. 로또·제휴마케팅처럼 현재 운영 여부가 확인되지 않은 실험은 활성 상태로 단정하지 않고 `실험 기록` 또는 `성과 검증 중`으로 표현한다.
5. 애드센스 승인과 실제 수익 발생을 구분한다.
6. 새 종료 포스트를 과거 트레이딩 기록의 후속 글로 연결한다.

## 변경 범위

### 신규 포스트

`_posts/2026-09-25-crypto-trading-experiment-on-hold.md`

- 자동매매 중단과 포지션 정리를 첫 문단에서 명시한다.
- 종료 이유를 단일 실패나 시장 전망으로 포장하지 않는다.
- 운영 복잡도, 자본 점유, 검증 비용, 기회비용을 중심으로 회고한다.
- 최종 실현손익이 확인되지 않았음을 숨기지 않는다.
- 기존 공개 수치는 종료 정산이 아닌 과거 스냅샷으로만 언급한다.
- 재개를 약속하지 않고, 현재는 다른 수익모델을 연구 중이라고 밝힌다.
- 투자 조언이 아니라 개인 프로젝트 회고임을 명시한다.
- 저작권 문제가 없는 deterministic Picsum 이미지를 사용한다.

### 메인 페이지

`index.html`

- SEO 설명과 소개 문구를 `현재 수익 발생`보다 `수익모델 검증` 중심으로 바꾼다.
- 트레이딩봇 카드를 `LIVE`에서 `실험 종료·보류`로 바꾼다.
- 로또 카드는 현재 자동 실행을 단정하지 않고 `자동화 실험 기록`으로 바꾼다.
- `다음 수익모델` 카드를 추가해 현재 방향을 노출한다.
- 블로그 포스트 수는 기존 동적 Liquid 값을 유지한다.

### 수익실험실

`_pages/lab.md`

- 현재 총자산처럼 보이는 307만 원과 목표 달성률을 상단에서 제거한다.
- 상단을 자산 대시보드가 아니라 실험 상태 대시보드로 재구성한다.
- 트레이딩 상태는 `종료·보류`, 포지션은 `정리 완료`로 표시한다.
- 과거 자산 숫자는 `공개 스냅샷` 섹션에 당시 기준으로 보존한다.
- 2026년 9월 종료·전환 행을 추가하되 최종 손익은 쓰지 않는다.
- 블로그 포스트 수는 `site.posts | size`로 동적 표시한다.
- 로또와 제휴마케팅은 현재 수익을 단정하지 않는다.
- 자동 갱신 주장을 제거하고 검증 후 수동 갱신 원칙을 쓴다.

### 소개 및 프로젝트 페이지

- `_pages/about.md`: 실제 운용 중 문구를 과거 실험과 현재 연구 방향으로 교체한다.
- `_projects/2026-01-trading-bot.md`: 개발 대기 상태를 실전 운영 종료·보류로 교체하고 과거 타임라인과 종료 글을 연결한다.
- `_projects/2026-02-tech-blog.md`: 16+ 포스트를 동적 값으로 바꾸고 오래된 로드맵과 수익 0원 단정을 정리한다.
- `_projects/2026-03-ai-agent.md`: 트레이딩 감시 크론과 8개 크론 현재형을 제거하고 초기 구현과 현재 활용을 구분한다.
- `_projects/2026-04-lotto-analyzer.md`: 자동 운영 중·1회 누적 수치를 현재 상태로 노출하지 않고 실험 기록으로 전환한다.
- `_posts/2026-05-24-trading-bot-v4-long-only-p2-dca-status.md`: 상단에 종료 포스트 후속 안내를 추가한다.

## 정보 구조

현재 상태는 세 단계로 읽히게 한다.

1. **메인:** 트레이딩 실험 종료와 다음 수익모델 탐색을 3초 안에 인지한다.
2. **수익실험실:** 활성·종료·검증 중 실험을 상태별로 구분한다.
3. **상세 글과 프로젝트 페이지:** 왜 종료했는지와 과거 기록을 확인한다.

## 표현 및 UI

- 상태는 색상뿐 아니라 `종료·보류`, `운영`, `실험 기록`, `연구 중` 텍스트로 구분한다.
- 종료 상태는 회색, 연구 중은 주황색, 운영 중인 블로그는 녹색 계열을 사용한다.
- 기존 인라인 스타일과 Jekyll Liquid 관례를 유지해 불필요한 CSS 리팩터링을 하지 않는다.
- 금액보다 상태와 검증 결과를 우선한다.

## 검증 기준

- 현재 상태 페이지에 `트레이딩봇 LIVE`, `실제 돈 넣고 운용 중`, 진행 중 포지션 문구가 남지 않는다.
- 신규 포스트와 프로젝트 페이지 간 종료 상태가 일치한다.
- 고정된 `101개`, `16+ 포스트`가 남지 않는다.
- Jekyll Docker 빌드가 성공한다.
- 신규 포스트와 메인·실험실·프로젝트 HTML이 생성된다.
- 내부 링크가 생성된 HTML 경로와 일치한다.
- `git diff --check`가 통과한다.
- 기본 브랜치가 아니라 별도 피처 브랜치를 업스트림에 push한다.

## 제외 범위

- 최종 실현손익 산출
- 현재 로또·애드센스·쿠팡 수익의 추정
- 과거 트레이딩 포스트 본문의 역사적 기록 재작성
- 디자인 시스템 전면 교체
- PR 생성 또는 병합
