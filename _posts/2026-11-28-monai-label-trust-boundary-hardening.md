의료 AI 서비스의 공격 표면은 모델 파일에만 있지 않다. 영상 이름, 데이터스토어 ID, 학습 설정, 원격 DICOM 서버가 돌려준 경로, 추론 결과 파일명도 모두 서버나 클라이언트의 파일 시스템과 명령 실행 경계에 닿는다. MONAI Label 0.8.8은 이 사실을 한 릴리스에 압축해 보여 준다.

2026년 11월 25일 공개된 MONAI Label 0.8.8은 모든 서버 배포뿐 아니라 Python 클라이언트와 3D Slicer 플러그인 사용자도 업데이트하라고 권고한다. 0.7.0~0.8.7의 bundle inference·training에서는 `$`로 시작하는 요청 문자열이 Python으로 평가될 수 있었고, 0.8.8은 요청값을 평문 데이터로 취급하도록 바꿨다. 유지관리자 검토에서는 training 설정, command line, DSA·DICOM proxy, 원격 서버 응답 경로, 클라이언트 결과 파일명 등 여러 경계 문제가 추가로 수정됐다.[1]

직전 0.8.7도 끝이 아니었다. 클라이언트가 제공한 `bundle_path`로 비인증 원격 코드 실행이 가능한 GHSA-j5c7-p3x5-gw2x는 0.6.0~0.8.6에 영향이 있고 0.8.7에서 패치됐다.[2] 그러나 유지관리자 종합 검토인 GHSA-xhxp-5f3g-gxxx는 0.8.7 이하 전체가 영향 범위이고 0.8.8에서 패치됐다.[3] 따라서 “0.8.7이니 최신 보안판”이라는 판정은 기준일에 틀리다.

## 1. 연속 보안 릴리스는 하나의 경계 지도로 읽는다

0.8.8 릴리스 노트는 서로 다른 결함 목록처럼 보이지만 공통 원인은 외부 입력이 더 강한 권한의 해석기로 승격되는 것이다. 요청 문자열이 Python 표현식으로 해석되고, 값이 compiler 또는 multi-GPU command line에 들어가며, 원격 데이터 소스가 돌려준 이름·경로·URL이 로컬 경로로 사용됐다. 서버가 보낸 결과 파일명을 Python·3D Slicer·CellProfiler·DSA CLI가 로컬 저장 경로로 신뢰한 문제도 포함된다.[1]

이를 데이터 흐름으로 나누면 네 경계가 보인다.

| 경계 | 비신뢰 입력 | 보호할 자원 |
|---|---|---|
| 클라이언트→서버 | 요청값, 파일명, image ID, bundle 경로 | 코드 실행, 서버 파일 시스템 |
| 원격 데이터 소스→서버 | DICOMweb·DSA·XNAT·CVAT의 이름·경로·URL | 토큰, 데이터스토어, 내부 네트워크 |
| 서버→데스크톱 클라이언트 | 결과 파일명과 메타데이터 | 사용자 워크스테이션 파일 |
| 관리자 기능→런타임 | reload, training, tracking 설정 | 서비스 구성과 프로세스 권한 |

버전 업데이트는 알려진 입력 경로를 수정한다. 운영 설계는 알려지지 않은 다음 결함의 피해 반경을 줄인다. 서버를 비특권 계정으로 실행하고 쓰기 가능 디렉터리를 데이터스토어로 제한하며, 인증과 역할을 켜고, 비신뢰 네트워크에서 서버를 분리하는 조치가 여기에 해당한다. 이는 릴리스 노트의 권고이기도 하다.[1]

## 2. 노출 자산은 서버와 클라이언트를 함께 찾는다

MONAI Label 0.8.8은 서버만 올리면 끝나는 수정이 아니다. 인벤토리에 다음 구성요소를 각각 넣는다.

- MONAI Label 서버 패키지·컨테이너와 실제 실행 버전
- 서버가 참조하는 app·bundle·model 저장 위치
- DICOMweb, DSA, XNAT, CVAT 같은 원격 데이터 소스와 서비스 계정
- Python client가 설치된 분석 환경과 자동화 작업
- 3D Slicer 플러그인, CellProfiler, DSA CLI가 설치된 워크스테이션
- 리버스 프록시, 인증 공급자, 네트워크 ACL과 외부 공개 경로

태그 이름이 아니라 이미지 다이제스트와 실행 컨테이너를 확인한다. 워크스테이션은 중앙 패키지 목록만 믿지 말고 플러그인 버전과 업데이트 성공 여부를 수집한다. 서버·클라이언트의 소유 팀이 다르면 동일한 변경 ID 아래 하위 작업으로 연결한다. 서버가 안전해도 오래된 클라이언트가 서버 제공 파일명을 로컬 경로로 신뢰하면 경계가 남는다.[1]

인증 기본값도 중요하다. 0.8.8 릴리스 노트는 `MONAI_LABEL_AUTH_ENABLE=False`로 인증이 기본 비활성화돼 있어, 서버에 연결할 수 있는 클라이언트가 문제 경로에 닿을 수 있다고 설명한다.[1] 그렇다고 모든 설치가 인터넷에 노출됐다고 단정해서는 안 된다. 실제 환경의 bind 주소, ingress, 방화벽, 보안 그룹, VPN, 프록시 인증을 읽기 전용으로 확인해 도달 범위를 판정한다.

자산 표에는 환자 데이터나 토큰을 넣지 않는다. 서비스 ID, 환경, 소유자, 제품 버전, 이미지 다이제스트, 인증 상태, 네트워크 범위, 연결된 데이터 소스 종류만 기록한다. 민감한 endpoint와 계정 이름은 접근 통제된 별도 문서에 둔다.

## 3. 패치 전에 신뢰 경계와 증거를 보존한다

인터넷이나 비신뢰 사용자에게 노출된 0.8.7 이하 서버는 우선 접근을 제한한다. 보안 그룹이나 ingress에서 승인된 관리·임상 네트워크만 허용하고, 필요하면 로드밸런서에서 격리한다. 단, 컨테이너를 즉시 삭제하거나 로그를 비우면 조사 자료가 사라진다. 이미지 다이제스트, 배포 정의, 프로세스 시작 시각, 인증·API·프록시 로그, 데이터스토어 파일 메타데이터를 먼저 보존한다.

의료 데이터 환경에서는 증거 수집도 최소 필요 원칙을 따라야 한다. 원본 영상이나 환자 식별자를 일반 사고 티켓에 복사하지 않는다. 로그의 URL·파일명·헤더에 PHI가 포함될 수 있으므로 보안·개인정보 담당자가 승인한 저장소와 보존 기간을 사용한다. 분석용 사본은 필요한 필드를 가명화하되 원본과의 체인 오브 커스터디를 유지한다.

초기 선별 항목은 다음과 같다.

- 예상하지 않은 bundle·app·tracking 설정 변경
- 서버 계정이 데이터스토어 밖 파일에 접근하거나 쓴 흔적
- training·inference 시점의 비정상 자식 프로세스와 외부 연결
- `/reload`, `/infer`, datastore·proxy 경로의 비정상 호출량과 실패
- DICOMweb·DSA·XNAT·CVAT 응답 뒤 생긴 낯선 로컬 경로
- 클라이언트 워크스테이션의 예상 밖 파일 생성·덮어쓰기
- 배포 시스템을 거치지 않은 코드·모델·구성 변경

이 신호들은 침해 확정 지표가 아니다. 정상 학습 작업도 자식 프로세스와 대용량 파일을 만든다. 작업 스케줄, 승인된 모델 배포, 사용자 세션과 시간축을 맞춰 판단한다. 반대로 알려진 문자열이나 파일 하나가 없다고 안전을 결론 내리지 않는다.

## 4. 0.8.8 패치와 최소 권한을 같은 변경으로 묶는다

공식 릴리스가 제시하는 설치 명령은 단순하지만, 운영에서는 패키지 출처·해시·이미지 다이제스트를 조직 정책에 따라 검증한 뒤 배포해야 한다. 이 글은 실제 환경에서 설치 명령을 실행하지 않는다. 목표 상태는 서버, Python client, 3D Slicer 플러그인을 모두 0.8.8 이상 지원 릴리스로 맞추는 것이다.[1]

패치와 함께 다음 경계를 줄인다.

1. 서버를 비특권 전용 계정으로 실행한다.
2. 루트 파일 시스템은 가능하면 읽기 전용으로 두고 쓰기는 전용 데이터·임시 디렉터리만 허용한다.
3. 인증을 활성화하고 admin·annotator 등 필요한 역할만 부여한다.
4. 액세스 토큰에는 만료를 두고 원격 데이터 소스별 계정을 분리한다.
5. 서버는 비신뢰 네트워크에 직접 노출하지 않고 프록시·ACL·TLS 경계를 둔다.
6. DICOMweb·DSA·XNAT·CVAT 목적지를 허용 목록으로 제한한다.
7. 클라이언트의 결과 저장 루트도 사용자별 전용 디렉터리로 한정한다.

0.8.8은 인증 사용 시 `/infer`의 `save_label`과 `/proxy/dicom` POST에 annotator 역할을 요구하고, `/reload`에는 admin 역할을 요구한다. 액세스 토큰 만료도 필수화한다.[1] 따라서 업데이트 뒤 기존 자동화가 더 강한 역할을 요구하거나 실패한다면 무조건 권한을 넓히지 않는다. 작업에 필요한 최소 역할을 확인하고 서비스 계정을 분리한다.

네트워크 격리는 인증을 대체하지 않고, 인증도 파일 시스템 최소 권한을 대체하지 않는다. 한 경계가 무너졌을 때 다음 경계가 피해를 제한하도록 독립 통제로 둔다.

## 5. 파괴적 재현 없이 거부와 정상 기능을 검증한다

경로 이탈이나 코드 실행을 확인하겠다고 시스템 파일, SSH 설정, 예약 작업을 대상으로 시험하면 안 된다. 검증이 필요하다면 운영 데이터가 없는 격리 환경에서 합성 의료 데이터와 전용 임시 루트만 사용한다. 외부 네트워크를 차단하고 비특권 사용자로 실행하며, 테스트가 임시 루트 밖에 쓰지 못하도록 컨테이너·샌드박스 정책을 둔다.

검증 계획은 정상과 거부를 나눠 설계한다.

- 허용된 확장자의 정상 영상 업로드·조회·추론·라벨 저장이 성공한다.
- 서버가 허용된 데이터스토어 루트 안에서만 파일을 만든다.
- 잘못된 image ID, 파일명, 결과 확장자, 정수가 아닌 제한 필드는 HTTP 400 등 문서화된 오류로 거부된다.
- 일반 사용자는 관리자 reload 기능을 호출할 수 없다.
- 원격 데이터 소스의 이름·경로·URL은 허용 루트와 목적지 안으로 제한된다.
- Python client와 3D Slicer는 결과를 승인된 로컬 디렉터리에 저장한다.
- 거부된 요청 뒤에도 부분 파일이나 임시 산출물이 승격되지 않는다.

위 항목은 **제안된 검증안**이다. 이 글을 작성하며 MONAI Label 환경에서 실행한 결과가 아니다. 실제 시험에서는 공격 페이로드를 재현하지 말고, 무해한 잘못된 값과 샌드박스 경계로 “승인 범위 밖 입력이 실패한다”는 성질만 확인한다.

정상 기능도 함께 본다. DICOM 조회, 이미지 로드, 추론, 라벨 저장, training queue, 플러그인 연동의 대표 흐름을 익명 합성 데이터로 확인한다. 서버 HTTP 200만으로 클라이언트 파일 저장과 역할 제어까지 검증됐다고 말하지 않는다.

## 6. 포렌식과 복구는 의료 데이터 경계를 보존한다

의심 징후가 있으면 영향 노드를 네트워크에서 격리하고 휘발성 증거 보존 여부를 사고 대응팀이 결정한다. 서버 계정이 접근할 수 있던 데이터스토어, 모델·bundle 저장소, 원격 데이터 소스 토큰, 클라이언트 결과 경로를 권한 기준으로 범위화한다. 취약점의 최대 영향만 보고 모든 환자 데이터가 유출됐다고 단정하지도, 명시적 다운로드 로그가 없다고 유출을 배제하지도 않는다.

복구는 신뢰할 수 있는 0.8.8 이상 이미지에서 새 서버를 만들고 검증된 구성과 데이터만 옮기는 방식이 바람직하다. 의심 컨테이너를 제자리 패치한 뒤 계속 쓰면 변경 흔적과 잔존 파일을 놓칠 수 있다. 노출 가능성이 있는 서비스 토큰과 인증 비밀은 새 환경이 격리된 상태에서 회전하고, 오래된 환경이 새 비밀을 받지 않게 한다.

종료 조건은 서버 버전 하나가 아니다. 서버·Python client·3D Slicer가 목표 버전이며, 인증과 역할이 적용되고, 쓰기 루트와 원격 목적지가 제한되고, 정상·거부 검증이 통과하고, 패치 전 노출 기간의 이상 검토가 끝나야 한다. 확인할 로그가 부족하면 “침해 없음” 대신 판정 제한으로 기록한다.

MONAI Label 0.8.8의 가장 큰 교훈은 의료 AI의 신뢰 경계가 모델 앞뒤 전체에 있다는 점이다. 요청을 데이터로만 다루고, 원격 응답을 다시 검증하고, 서버가 보낸 파일명도 클라이언트가 제한하며, 각 프로세스가 최소한의 디렉터리만 쓸 수 있게 해야 한다. 버전 패치는 출발점이고, 서버에서 데스크톱까지 이어지는 경계가 실제 방어선이다.
