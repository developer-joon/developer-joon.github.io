Mitel은 2026년 11월 16일 MiCollab의 Audio, Web and Video Conferencing(AWV) 구성요소에서 발견된 다섯 취약점을 공개했고 11월 24일 공지를 갱신했다.[1] 다음 날 CISA는 다섯 CVE를 모두 Known Exploited Vulnerabilities(KEV) 카탈로그에 추가했다. KEV 등재는 각 항목에 실제 악용 증거가 있다는 뜻이며, 특정 조직의 MiCollab이 침해됐다는 판정은 아니다.[2]

이 사건은 취약점 관리에서 “가장 높은 CVSS 하나부터 처리한다”는 방식의 한계를 보여 준다. 같은 외부 노출 구성요소에 파일 업로드, XML 주입, 약한 인증, 명령 주입, 인증 실패 처리 문제가 모여 있다. Mitel도 이 문제들을 함께 악용하면 영향이 크게 커질 수 있다고 설명한다.[1] 방어팀은 공격 순서를 재현하는 대신 다섯 항목을 하나의 **AWV 노출·패치·침해 선별 묶음**으로 다뤄야 한다.

## 다섯 CVE를 한 줄의 점수표로만 보지 않는다

Mitel 공지의 범위는 모두 MiCollab AWV 구성요소다. CVE-2026-133275는 파일 형식 검증 부족으로 인한 임의 파일 업로드, CVE-2026-133303은 매개변수 검증 부족과 관련된 XML 주입, CVE-2026-133311은 인증 메커니즘 문제로 인한 제한된 기능의 무단 접근이다. CVE-2026-133323은 명령 주입, CVE-2026-133324는 인증을 안전하게 실패시키지 못하는 문제로 설명된다.[1]

개별 심각도는 서로 다르다. 파일 업로드와 무단 접근 항목이 Medium이라고 해서 뒤로 미루면 안 된다. 같은 외부 표면에 존재하고, 공급자가 결합 시 영향 증폭 가능성을 명시했으며, CISA가 다섯 항목 모두를 KEV에 올렸기 때문이다.[1][2] 이는 “실제로 특정한 순서로 체인이 관찰됐다”는 주장과는 다르다. 공개 공지가 증명하는 것은 각 CVE의 실제 악용 근거와 결합 위험에 관한 공급자 경고다. 구체적인 공격 순서나 페이로드는 방어 우선순위 설정에 필요하지 않다.

운영 큐에서는 다음처럼 묶는다.

| 우선순위 조건 | 조치 |
|---|---|
| 인터넷에서 AWV에 직접 도달 가능 | 즉시 외부 경로 제한, 증거 보존, 긴급 패치 |
| 파트너망·VPN에서 넓게 도달 가능 | 접근 주체 축소, 인증·업로드·프로세스 로그 선별, 패치 |
| 내부 전용이지만 불특정 사용자 접근 가능 | 로컬 노출과 권한 확인, 유지보수 창을 앞당겨 패치 |
| 자산 존재 여부 불명 | DNS·프록시·방화벽·CMDB·패키지 정보를 교차해 판정 |

“내부망”은 자동으로 낮은 위험을 뜻하지 않는다. 회의 시스템은 여러 사용자와 디렉터리, 메일, 브라우저가 만나는 서비스다. 외부 프록시가 없어도 게스트 네트워크나 협력사 VPN에서 접근할 수 있다면 별도의 노출 경로다. 자산 소유자가 불명확하거나 접근 경로를 증명하지 못한 시스템은 낮은 우선순위로 내리지 말고, 확인이 끝날 때까지 노출 후보로 유지한다.

## AWV 자산과 실제 도달 경로부터 확정한다

인벤토리는 제품명 문자열만 검색해서 끝내지 않는다. 공급자 공지상 영향 조건은 **지원되는 MiCollab 10.3의 10.3.0.18 및 이전 버전**이다. 공지는 지원 종료(EoS) 제품의 영향 여부는 판정하지 않으므로, 이 조건을 EoS 자산의 안전 판정에 그대로 사용해서는 안 된다.[1] MiCollab 인스턴스, 설치 버전, AWV 활성 여부, 가상 IP와 DNS, 로드 밸런서, 리버스 프록시, WAF, 방화벽, VPN 경로를 하나의 행으로 연결한다. 폐기 예정 장비, 재해복구 인스턴스, 테스트 환경, 과거 DNS가 남은 복제본도 찾는다.

외부 노출 판정에는 승인된 네트워크 관측과 구성 검토를 사용한다. 인터넷 전역을 공격적으로 스캔하거나 취약 요청을 보내지 않는다. 클라우드 보안 그룹과 온프레미스 NAT, 프록시의 업스트림 목록, 인증서 투명성 로그에서 발견한 이름을 CMDB와 대조하되, 발견된 호스트에 대한 접근 권한을 먼저 확인한다.

최소 인벤토리 필드는 다음과 같다.

- 자산 소유자와 업무 중요도
- MiCollab 전체 버전 및 AWV 구성요소 상태
- 인터넷·파트너·내부 사용자별 도달 경로
- 공급자 패치 적용 여부와 변경 티켓
- 로그 위치, 보존 기간, 시간 동기화 상태
- 디렉터리·메일·파일 저장소 등 외부 연동
- 백업 시각과 복구 시험 상태

버전만 적고 로그 위치를 비워 두면 패치 전에 필요한 증거를 잃기 쉽다. 로그 보존 기간이 짧다면 유지보수 작업보다 먼저 읽기 전용 사본을 만든다. 수집 시각, 원본 경로, 해시와 담당자를 기록해 이후 분석의 연속성을 유지한다.

## 패치와 임시 접근 제한을 같은 변경으로 실행한다

Mitel은 MiCollab 10.3.0.18용 패치와 이후 릴리스에서 해결책을 제공한다고 공지한다. **10.3.0.18은 그 자체로 수정 버전이 아니다.** 이 빌드에 도달한 자산도 KB000129195에서 제공하는 별도 패치를 적용해야 하며, 대안은 공급자가 명시한 이후 릴리스로 업그레이드하는 것이다.[1] 실제 적용 대상과 파일은 고객 지원 채널의 현재 지침을 확인해야 한다. “10.3 계열”처럼 넓은 버전 표기나 `10.3.0.18` 버전 문자열만으로 성공을 판정하지 말고, 설치된 빌드와 별도 패치 적용 증거를 자산별로 기록한다.

유지보수 창 전에는 AWV 외부 접근을 승인된 사용자와 네트워크로 좁힌다. 회의 기능을 중단하기 어렵다면 게스트 접근, 관리 경로, 사용자 회의 경로를 나눠 최소한의 허용 목록을 만든다. 임시 WAF 규칙은 알려진 공격 형태를 일부 줄일 수 있지만, 다섯 취약점의 모든 입력 변형을 막는다는 근거가 없다. 패치 대신 “가상 패치 완료”로 기록하지 않는다.

배포 후에는 세 가지를 확인한다.

1. 설치 관리 도구가 성공을 반환했고 대상 빌드가 공급자 수정선과 일치한다.
2. 실제 서비스를 제공하는 프로세스가 패치 뒤 재시작됐으며 클러스터의 모든 노드가 같은 수준이다.
3. 정상 사용자 로그인, 회의 생성·참가, 승인된 파일 기능과 관리 화면이 회귀 점검을 통과한다.

공격용 XML, 명령 문자열, 우회 요청, 임의 파일 업로드를 운영 환경에 보내는 검증은 하지 않는다. 공급자 패치 증거와 정상 기능의 부정적 회귀 점검으로 배포를 확인한다. 더 강한 보안 시험이 필요하면 운영 데이터와 분리된 승인된 테스트 환경에서 전문 팀이 별도 계획으로 수행한다.

## 탐지는 업로드·인증·프로세스·설정 네 축으로 넓힌다

다중 취약점 대응에서 하나의 URI나 오류 코드만 찾으면 쉽게 놓친다. 공개 공지의 취약점 클래스와 시스템의 정상 기준을 이용해 이상 행위를 선별한다.

**업로드 축**에서는 평소 사용하지 않는 파일 형식, 비정상 크기·빈도, 업무 시간 밖의 업로드, 업로드 직후 생성·변경된 실행 가능 파일을 확인한다. 파일 내용을 실행하거나 샘플을 운영 호스트에서 열지 않고 격리된 분석 절차로 넘긴다.

**인증 축**에서는 성공과 실패 비율, 동일 출발지의 여러 계정 접근, 정상 세션 생성 없이 이어진 민감 기능 접근, 새 관리자·권한 변경을 본다. CVE-2026-133311의 영향은 공지상 특정 기능에 제한되고 시스템의 임의 파일 전체 접근을 뜻하지 않는다는 경계도 유지한다.[1]

**프로세스 축**에서는 AWV 서비스 계정이 평소 실행하지 않는 자식 프로세스, 예기치 않은 네트워크 연결, 새 서비스·예약 작업, 웹 디렉터리 밖 파일 변경을 찾는다. 프로세스 이름 하나만으로 악성이라고 단정하지 말고 실행 경로, 부모, 시작 시각, 파일 해시와 변경 티켓을 연결한다.

**설정 축**에서는 인증 정책, 프록시 대상, 디렉터리 연동, 로깅, 회의 권한, 새 계정과 인증서 변경을 비교한다. 기준 구성 스냅샷이 없다면 “현재 상태가 정상”이라고 가정하지 말고, 소유자 확인과 변경 기록으로 설명 가능한 항목을 분리한다.

## 발견된 징후는 패치 성공과 별도로 처리한다

패치 뒤 정상 기능이 동작해도 패치 전 악용 흔적이 사라지지는 않는다. 의심스러운 업로드, 비정상 프로세스, 무단 인증 또는 설정 변경이 발견되면 해당 노드를 격리하고 증거를 보존한다. 디렉터리, 메일, 통화·회의 데이터 저장소와 관리 계정의 인접 로그까지 조사 범위를 넓힌다.

자격 증명 회전은 일괄 비밀번호 변경으로 끝내지 않는다. 노출 가능성이 있는 서비스 계정, API 토큰, 인증서 개인키와 관리자 세션을 목록화하고 실제 폐기 여부를 확인한다. 손상 가능성이 있는 호스트에서 새 비밀을 생성하거나 입력하지 않는다. 재구축이 필요하다면 신뢰할 수 있는 설치 매체와 현재 패치를 사용하고, 이전 구성은 차이 검토 후 필요한 항목만 옮긴다.

아무 IoC도 찾지 못한 경우에도 로그가 노출 기간 전체를 덮는지 확인한다. 보존 공백, 시간 불일치, 비활성화된 감사 기능이 있다면 결론은 “침해 없음”이 아니라 “현재 증거에서 확인되지 않음”이다. 이 불확실성을 잔여 위험으로 남겨 비밀 회전이나 예방적 재구축 여부를 결정한다.

## 종료 기준은 다섯 CVE를 하나의 운영 단위로 본다

이 사건의 패치 티켓을 CVE별 다섯 장으로만 나누면 한 항목이 빠진 자산이 생길 수 있다. 자산별 종료 기준을 만들고 다섯 항목의 패치가 같은 증거로 충족되는지 확인한다.

- 모든 MiCollab·AWV 자산과 도달 경로가 식별됐다.
- 인터넷과 넓은 파트너 접근이 제거되거나 명시적으로 승인됐다.
- 10.3.0.18 자산에는 KB000129195의 별도 패치가 적용됐거나, 모든 영향 자산이 공급자가 명시한 이후 릴리스로 업그레이드됐다.[1]
- 업로드, 인증, 프로세스, 설정 변경 로그가 노출 기간에 대해 검토됐다.
- 발견된 이상 징후마다 조사 결과와 후속 조치가 연결됐다.
- 정상 회의·로그인·관리 기능의 회귀 점검 기록이 남았다.
- 로그 공백과 미확인 자산의 책임자, 기한, 위험 수용 여부가 정해졌다.

KEV는 우선순위를 높이는 강한 신호지만 복구 판정 도구는 아니다. 개별 CVSS만 보는 대신 동일 구성요소, 실제 악용, 결합 가능성, 외부 도달성, 증거 가용성을 함께 보면 패치와 탐지가 같은 방향으로 움직인다. 이것이 이번 MiCollab 공지에서 가져가야 할 운영 원칙이다.
