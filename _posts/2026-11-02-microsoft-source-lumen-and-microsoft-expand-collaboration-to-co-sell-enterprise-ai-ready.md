마이크로소프트와 루멘은 2026년 11월 2일 Azure 기반 AI 프로젝트와 네트워크 현대화를 함께 판매하는 협력을 확대한다고 발표했다. 양사는 온프레미스, 데이터센터, 지사와 여러 클라우드에 흩어진 데이터·애플리케이션을 연결하는 문제를 공동 계정계획과 판매 경로에서 다루겠다고 밝혔다.[1]

이 발표는 특정 고객의 지연시간이나 비용이 줄었다는 성과 보고가 아니다. 구체적인 도입 수, 매출, 성능 개선과 비용 절감 결과는 공개되지 않았다. Alkira 기반 Lumen Connect는 이미 Microsoft Marketplace에서 구매할 수 있지만, 루멘의 전체 기능이 Azure에 통합됐다는 뜻도 아니다.[1][2]

## AI 데이터 경로를 먼저 그리기

모델 API 한 번을 호출해도 데이터는 여러 경계를 지난다.

```text
지사·사용자
  → 온프레미스 애플리케이션
  → 사설/공용 연결
  → Azure 데이터·AI 서비스
  ↔ 다른 클라우드의 저장소·서비스
  → 관측·보안·감사 시스템
```

각 화살표에는 왕복 지연, 대역폭, 이그레스 요금, 암호화 종료점, ID 전달, 장애 도메인과 로그 소유자가 있다. GPU 가격만 비교하고 이 경로를 빼면 PoC에서는 작동하지만 운영비와 복구시간이 예상보다 커질 수 있다.

## 사전 점검표: 속도보다 경계를 측정한다

| 항목 | 확인 질문 | 측정 방법 |
|---|---|---|
| 지연시간 | 사용자 요청과 배치 전송의 허용치가 다른가 | p50·p95·p99, 지역·시간대별 |
| 대역폭 | 학습·RAG·백업 피크가 겹치는가 | 방향별 처리량·혼잡 |
| 이그레스 | 어느 경계에서 데이터 반출료가 붙는가 | GB당 단가와 월간 흐름 |
| 장애 | 회선·라우터·클라우드 리전의 실패가 분리되는가 | 장애주입·전환시간 |
| ID | 사용자·서비스 주체가 끝까지 보존되는가 | 토큰·인증서·권한 추적 |
| 정책 | 방화벽·DLP·세분화 규칙이 여러 경로에 일관적인가 | 정책 배포·드리프트 검사 |
| 관측성 | 한 요청을 종단 간 연결할 수 있는가 | trace ID·flow log 상관 |

“단일 포털”이나 “일관된 정책”은 제품 목표이지 검증 결과가 아니다. 실제 계정·리전·경로에서 정책이 같은 의미로 적용되는지 시험해야 한다.

## 이그레스 비용은 평균 GB보다 재시도를 포함해야 한다

AI 워크로드는 원본 문서, 벡터, 모델 입력·출력, 체크포인트와 로그를 이동시킨다. 장애나 시간초과로 재시도하면 같은 데이터가 다시 흐를 수 있다. 캐시 적중률이 낮거나 데이터 주권 때문에 처리 위치가 제한되면 경계 통과가 늘어난다.

비용표에는 정상 트래픽뿐 아니라 재시도, 백업, 복제, 보안 로그와 장애 시 우회 경로를 포함해야 한다. Marketplace를 통한 구매가 청구를 단순화할 수는 있어도 네트워크 사용량 자체를 없애지는 않는다.

## 멀티클라우드 일관성은 가장 약한 경계에서 깨진다

Azure Virtual WAN, 루멘 연결과 Alkira 같은 오케스트레이션을 함께 사용할 수 있지만 각 계층이 보는 객체와 정책 언어가 다를 수 있다.[1] 한 곳의 `deny`가 다른 곳에서는 라우팅만 차단하거나, 로그에 사용자 ID 대신 중간 게이트웨이 주소만 남을 수 있다.

정책 변경은 `설계→시뮬레이션→제한된 적용→흐름 로그 확인→확대` 순서로 배포하는 편이 안전하다. 롤백 때 라우팅 테이블, 방화벽, DNS와 인증서가 같은 버전으로 돌아가는지도 확인해야 한다.

## 공동판매와 기술 통합을 분리하기

이번 발표에는 세 층이 있다.

1. 양사의 공동 계정계획과 판매 협력 확대
2. 현재 Marketplace에서 이용 가능한 Alkira 기반 Lumen Connect
3. 향후 더 많은 루멘 기능을 Azure·Marketplace에 제공할 기회와 에이전트 거버넌스 협력 탐색

세 번째 층은 계획이다. 제품 선택 문서에서 미래 통합을 현재 제공 기능처럼 요구사항에 넣으면 구매 뒤 공백이 생길 수 있다. 계약에는 현재 제공되는 SKU, 리전, SLA, 지원 책임과 로드맵 항목을 별도 부록으로 두는 것이 좋다.

## 네트워크를 AI 사업계획의 뒤쪽에 두지 않기

AI 프로젝트의 실패 원인이 항상 모델 품질인 것은 아니다. 데이터가 필요한 위치에 제때 도착하지 않거나, 경계마다 비용과 보안정책이 달라 운영 전환이 멈출 수 있다. 마이크로소프트·루멘 발표는 이 문제를 클라우드 현대화 초기에 다루겠다는 공동판매 계획이다.[1]

검증의 기준은 발표문이 아니라 실제 데이터 경로다. 지연, 비용, 장애, ID, 정책과 관측성을 PoC 전부터 같은 표에 놓아야 한다. 협력 확대는 출발점이며, 고객 환경의 성능·비용 개선은 별도 측정으로 증명해야 한다.
